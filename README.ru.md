# ShadowGarlic

**Русский** · [English](README.md)

Два docker compose окружения: **сервер** (i2pd + ssserver-rust) и **клиент**
(i2pd + sslocal-rust). Трафик из обычного интернета идёт через Shadowsocks,
зашитый в I2P-стримы между серверным и клиентским туннелями i2pd.

```
           КЛИЕНТ                                     СЕРВЕР
┌───────────────────────────┐               ┌────────────────────────┐
│    Приложение на хосте    │               │   В обычный интернет   │
│            │              │               │            ▲           │
│            ▼              │               │            │           │
│      sslocal-rust         │               │            │           │
│   SOCKS5 127.0.0.1:1080   │               │   ssserver-rust:8388   │
│            │              │               │            ▲           │
│            ▼              │               │            │           │
│           i2pd            │      I2P                i2pd           │
│    client tunnel :7655 ─────────────────────> server tunnel :8388  │
└───────────────────────────┘               └────────────────────────┘
```

- Клиентский i2pd поднимает туннель до **b32-адреса сервера** и слушает TCP на
  порту `7655`; sslocal подключается к этому порту и отдаёт SOCKS5-прокси на хост.
- sslocal шифрует трафик, i2pd доставляет его по I2P до серверного туннеля,
  i2pd на сервере форвардит на ssserver, тот расшифровывает и выходит в интернет.

## 1. Настройка сервера

```bash
git clone https://github.com/minbbb/ShadowGarlic
cd ShadowGarlic
cp .env.example .env
```

Отредактируйте `.env`:

| Переменная            | По умолчанию               | Назначение                                                                                           |
| --------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------- |
| `SS_METHOD`           | `aes-256-gcm`              | Шифр shadowsocks                                                                                     |
| `SS_PASSWORD`         | `ChangeMe_strong_password` | Пароль shadowsocks - **обязательно смените**                                                         |
| `SS_SERVER_PORT`      | `8388`                     | Порт ssserver внутри compose-сети. Должен совпадать с `port = 8388` в `config/tunnels.conf.template` |
| `SS_LOCAL_PORT`       | `1080`                     | Порт SOCKS5 на клиенте (хост)                                                                        |
| `I2PD_CONSOLE_PASS`   | `ChangeMe_strong_password` | Пароль вебконсоли i2pd (Basic Auth) - **обязательно смените**                                        |
| `I2P_INBOUND_LENGTH`  | `3`                        | Хопы входящего (inbound) I2P-туннеля (0-8) - см. раздел ниже                                         |
| `I2P_OUTBOUND_LENGTH` | `3`                        | Хопы исходящего (outbound) I2P-туннеля (0-8) - см. раздел ниже                                       |
| `I2PD_IMAGE_TAG`      | `release-2.61.0`           | Тег образа i2pd                                                                                      |
| `SS_IMAGE_TAG`        | `v1.25.0`                  | Тег образа shadowsocks-rust                                                                          |

> ВАЖНО про пароли (`SS_PASSWORD` и `I2PD_CONSOLE_PASS`): избегайте символов
> `$`, `"`, `\` - они ломают интерполяцию compose (значения уходят в
> CLI-аргументы `-k ...` и `--http.pass="..."`).

Запуск:

```bash
docker compose up -d
```

Проверить что запустились:

```bash
docker compose ps
```

### Получение b32-адреса серверного туннеля (нужен клиенту)

Первый запуск создаёт ключи `shadowsocks.dat` и после построения lease set
логирует адрес:

```bash
docker compose logs i2pd | grep "Local address"
# Пример вывода:
# Clients: Local address bg3............m.b32.i2p loaded
```

Либо откройте вебконсоль, пробросив порт по SSH
(`ssh -p 22 -L 7070:127.0.0.1:7070 root@<IP_сервера>` → на пк откройте `http://localhost:7070`, логин `i2pd`,
пароль - значение `I2PD_CONSOLE_PASS` из `.env`) → страница **I2P tunnels**
→ секция **Server tunnels**: там же будет `<b32>.b32.i2p`.

> Вебконсоль напрямую по `http://<IP_сервера>:7070` недоступна: docker compose
> публикует порт только на `127.0.0.1`, а сама консоль защищена Basic Auth.

### Настройка количества хопов (I2P)

Длину I2P-туннелей задают две переменные `.env`:

| Переменная            | Диапазон | По умолчанию | Что задаёт              |
| --------------------- | -------- | ------------ | ----------------------- |
| `I2P_INBOUND_LENGTH`  | 0-8      | `3`          | Хопы входящего туннеля  |
| `I2P_OUTBOUND_LENGTH` | 0-8      | `3`          | Хопы исходящего туннеля |

- Меньше хопов → ниже латентность и выше скорость, но слабее анонимность.
- Как настраивается технически: значения из `.env` передаются в контейнер
  через `environment:`, а entrypoint контейнера i2pd подставляет их в
  `inbound.length`/`outbound.length`:
    - сервер - рендером шаблона `config/tunnels.conf.template` в
      `/home/i2pd/data/tunnels.conf`;
    - клиент - инжекцией в ваш `client/tunnels.conf` (файл с b32-адресом).
- Применить после правки `.env`: `docker compose up -d` (изменение значения
  пересоздаёт контейнер i2pd, тот перестраивает туннели с новой длиной).
- Проверить фактическую длину отдельных туннелей можно по логу i2pd
  (`docker compose logs i2pd | grep "Parameters for tunnel"`): i2pd при
  построении печатает строку вида `5 inbound (3 hops), 5 outbound (4 hops)`.

### Сброс адреса (удаление volume)

Адрес серверного туннеля (`shadowsocks.dat`, b32-адрес), netdb и остальные
данные i2pd хранятся в named volume `shadowgarlic_i2pd-data`. Чтобы сбросить
их и получить **новый b32-адрес**:

```bash
# на сервере:
docker compose down -v                   # останавливает контейнеры и удаляет volume
docker volume rm shadowgarlic_i2pd-data  # просто удалить volume
```

> ⚠️ После сброса адрес меняется - обновите `destination` в
> `client/tunnels.conf` на клиенте (см. шаг 2), иначе клиентский туннель
> не свяжется с сервером. Клиентский volume сбрасывается аналогично:
> `docker compose -f docker-compose.client.yml down -v`.

## 2. Настройка клиента

На клиентской машине:

```bash
# 1. Создаём .env из шаблона:
cp .env.example .env
```

Либо скопируйте .env с сервера

> `SS_PASSWORD` и `SS_METHOD` на клиенте **обязаны совпадать** с серверными.
> `I2PD_CONSOLE_PASS` и `SS_LOCAL_PORT` - по желанию (у клиента
> консоль на хост не публикуется, а SOCKS5-порт настраивается этим файлом).

```bash
# 2. Скопируйте конфигурацию туннеля из шаблона:
cp client/tunnels.conf.example client/tunnels.conf
```

Откройте `client/tunnels.conf` и подставьте b32-адрес из шага выше:

```
destination = <b32-адрес>.b32.i2p
```

Запуск:

```bash
docker compose -f docker-compose.client.yml up -d
```

### Использование с телефона

Либо прокси можно использовать с телефона: поднимите туннель в I2P-приложении по b32-адресу сервера и подключитесь к нему любым
клиентом, поддерживающим Shadowsocks, с `SS_PASSWORD`/`SS_METHOD` из `.env`.
В I2P-приложении укажите серверный `destinationport` (`8388` по умолчанию) и
локальный порт (например, `7655`) - shadowsocks-клиент подключается к
`127.0.0.1:7655`.

## 3. Проверка работы

На клиенте:

```bash
curl -x socks5h://127.0.0.1:1080 https://api.ipify.org
```

Вернётся **публичный IP сервера**.

> Обратите внимание на `socks5h` (домен резолвится через прокси - на стороне
> сервера). С `socks5` (без `h`) домен резолвится локально системным
> резолвером клиента и через туннель не пойдёт.

На сервере проверьте активность туннеля через вебконсоль
(`http://localhost:7070` после SSH-проброса, см. выше → I2P tunnels).

Посмотреть логи:

```bash
docker compose logs -f i2pd                                # логи серверного i2pd
docker compose -f docker-compose.client.yml logs -f i2pd   # логи клиентского i2pd
```

## Ограничения и замечания

- **Клиентский SOCKS5 (порт `SS_LOCAL_PORT`) публикуется на `0.0.0.0`** - прокси
  без аутентификации доступен всем устройствам в локальной сети хоста.
  Если доступ нужен только с самой машины смените на
  `127.0.0.1:${SS_LOCAL_PORT}:${SS_LOCAL_PORT}` в `docker-compose.client.yml`.
- **Вебконсоль i2pd защищена Basic Auth** (пароль `I2PD_CONSOLE_PASS` из `.env`);
  на сервере порт 7070 привязан к `127.0.0.1`, доступ - через SSH-проброс.
